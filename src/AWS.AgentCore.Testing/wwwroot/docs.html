Chat App Documentation

A web-based testing interface for interacting with your AWS Bedrock AgentCore agent during local development.

Overview

The Chat App provides a conversational UI for testing your AgentCore agent without writing client code. It communicates with the Runtime Emulator via the AWS SDK, simulating how real clients will invoke your agent in production.

Key capabilities:

  • Send messages and receive agent responses (with streaming support)
  • Customize the JSON payload structure your agent receives
  • Define reusable parameters that appear as input fields
  • Manage multiple chat sessions
  • Render Markdown responses with syntax highlighting
  • Persist your payload configuration across restarts

Quick Start

  1. Your Aspire app host starts the Chat App automatically when you call AddAgentCoreRuntime<T>().
  2. Click the "Chat" link in the Aspire Dashboard to open the Chat App.
  3. Type a message and press Enter to send it to your agent.
  4. If your agent expects a different JSON shape, open the Payload Editor (code icon in the header) to configure it.
Tip Click "Send test message" on the welcome screen to quickly verify your agent is responding.

Sending Messages

Type your message in the input box at the bottom and press Enter to send. The message text is injected into your payload template at the {{input}} placeholder, and the resulting JSON is sent to the Runtime Emulator which forwards it to your agent's /invocations endpoint.

If your agent supports streaming, responses appear incrementally as tokens arrive. A typing animation indicates the agent is processing your request.

Stop Generation

While the agent is responding, a stop button appears next to the input. Click it (or press Escape) to cancel the in-flight request. The partial response received so far is preserved in the chat.

Sessions

The sidebar on the left shows your chat sessions. Each session maintains its own message history.

  • New Chat — Click the "+" button to start a fresh session.
  • Switch sessions — Click any session in the sidebar to view its messages.
  • Delete a session — Hover over a session and click the trash icon.
  • Auto-titling — Sessions are automatically titled from your first message.

Sessions are stored in-memory on the server. They persist as long as the app host is running but are lost on restart.

Note The session ID is passed as a header to the Runtime Emulator. Your agent can use it to maintain conversational context across multiple turns.

Payload Editor

The Payload Editor lets you define the exact JSON structure your agent expects. Open it by clicking the code icon (</>) in the header bar, or click "Configure payload" on the welcome screen.

The editor supports:

  • Full JSON editing with line numbers
  • Real-time validation (invalid JSON shows an error below the editor)
  • Auto-formatting (click "Format" to prettify)
  • Placeholder substitution with {{paramName}} syntax
  • A live preview showing the resolved payload

Default Payload

By default, the Chat App sends:

{
  "prompt": "{{input}}"
}

Where {{input}} is replaced by whatever you type in the chat box. If your agent expects a different shape, edit the template to match.

Example: Custom Agent Payload

If your agent handler expects this structure:

public record MyRequest(string UserMessage, string Model, int MaxTokens);

Configure your payload template as:

{
  "userMessage": "{{input}}",
  "model": "{{model}}",
  "maxTokens": {{maxTokens}}
}

Then add model and maxTokens as parameters (see below).

Parameters

Parameters are named placeholders in your template that become input fields in the chat area. They appear as small text boxes above the main chat input.

Adding Parameters

  1. Open the Payload Editor.
  2. In the Parameters section, click Add.
  3. Enter a name (must match a {{name}} in your template).
  4. Set a default value.
  5. Choose a type: string, number, boolean, or raw.

Parameter Types

TypeBehaviorExample Output
string Value is wrapped in quotes "hello"
number Value inserted without quotes 42
boolean Value inserted without quotes true
raw Value inserted as-is (for objects/arrays) {"key": "val"}
Note The {{input}} placeholder is always available and maps to the main chat text box. You don't need to define it as a parameter.

The Payload Editor includes built-in templates for common agent patterns. Click a template to load its payload structure and parameters instantly.

Tip Use templates as a starting point, then customize the payload and parameters to match your agent's exact schema.

Streaming

When your agent is configured with .WithStreaming(), the Chat App uses Server-Sent Events (SSE) to receive responses incrementally. A "Streaming" badge appears in the header when this mode is active.

In streaming mode:

  • Responses render token-by-token as they arrive
  • You can stop generation mid-response
  • Markdown is rendered progressively

Non-streaming mode waits for the full response before displaying it. Both modes support full Markdown rendering.

Payload Structure

Understanding how the Chat App builds the final request helps you configure it correctly. When you send a message, here's what happens:

  1. Your template is taken as a string (e.g., {"prompt": "{{input}}"}).
  2. Each {{paramName}} is replaced with the corresponding parameter value:
    • {{input}} — the text you typed in the chat box
    • {{otherParam}} — the value from the parameter input field
  3. The substituted string is sent as the request payload.
  4. The Runtime Emulator passes this payload directly to your agent's /invocations body.
Important String-type parameters are automatically quoted. If your template already has quotes around the placeholder (e.g., "field": "{{param}}"), make sure the parameter type is string. For numeric or boolean values, omit the quotes in the template and use the appropriate type.

Persistence

Your payload configuration (template + parameters) is automatically saved and restored across sessions. Changes are persisted after a 1-second debounce to avoid excessive writes.

  • Storage location — ~/.agentcore/testing/{agentName}/payload-config.json
  • Per-agent — Each agent has its own config, so switching between agents preserves each one.
  • Reset — Click the "Reset" button in the Payload Editor header to restore the default template.

Theme preference (light/dark) is stored as a browser cookie and applies globally across all agents.

Theme

Click the sun/moon icon in the header to toggle between dark and light mode. The preference is stored in a cookie and remembered across browser sessions.

Troubleshooting

Agent returns an error

If your agent throws an exception or returns a non-200 status code, the error message will appear in the chat as a system message. Check the Aspire Dashboard logs for the full stack trace.

Messages not appearing

Ensure your agent is running and responding on its HTTP endpoint. You can verify by clicking the "Agent Instance" link in Aspire — it should show the agent info page with a healthy /ping endpoint.

Payload format mismatch

If your agent returns a deserialization error, the JSON payload shape likely doesn't match your agent's request model. Open the Payload Editor, check the Live Preview to see the exact JSON being sent, and compare it to your agent's TRequest type.

Streaming not working

Streaming requires your agent to be registered with .WithStreaming() in the Aspire app host. If the "Streaming" badge is not visible in the header, streaming is not enabled for this agent.

Configuration not persisting

Payload configuration is saved to disk at ~/.agentcore/testing/{agentName}/. Ensure the process has write access to your home directory. If the agent name changes between runs, a fresh configuration will be created.
